### 0.9
只有一个请求行，没有请求头和请求体；返回也没有头信息，只有数据
传输通过ASCII字符流

### 1.0
有头有体，返回也有状态码
提供了cache机制
加入了User-Agent

### 1.1
持久连接,Keep-Alive
管线化解决队头阻塞问题
提供虚拟主机的支持(Host字段)
数据分块传输
Cookie机制和安全机制

### 2.0
出现原因:
1. TCP慢启动，导致一些很小的资源受到影响，它们本来应该很快速响应；慢启动是减少网络拥塞的一种策略，无法改变
2. 多条TCP连接竞争固定的带宽
3. 队头阻塞问题，1.1不成熟的管线化并没有解决这个问题
4. 协议开销过大，headers里内容过大无法压缩，增加传输成本

新增特性:
1. 多路复用
2. 头部压缩
3. 服务器推送
4. 设置请求优先级
5. 可在不断开TCP下取消请求

### 3.0
TCP层面依旧存在队头阻塞
TCP建立连接的延时，握手造成了一定的耗时
TCP协议僵化

解决方案：底层用UDP协议的QUIC协议
1. 握手低延时
2. 彻底解决队头阻塞
3. 实现了类似TCP的流量控制和可靠性传输
4. 集成TLS加密能力
5. 实现2.0多路复用
6. 更好的错误处理能力
