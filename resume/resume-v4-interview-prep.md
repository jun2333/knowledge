## 一、简历话术地图

简历上每一个"亮点"都是一个**待引爆的追问点**。面试官看到数字一定会问"这个怎么来的"。

| 简历上的表述 | 面试官大概率追问 | 你必须能答出的细节 |
|-------------|----------------|------------------|
| 主导 5+ 子应用微前端落地 | "微前端怎么做的？遇到什么问题？" | 技术选型理由 → 沙箱隔离方案 → 通信机制 → **踩过的坑** |
| 单份模板维护 **2 小时 → 分钟级** | "这个数据怎么来的？" | 旧流程（Word 留白 → 转 PDF → 标注变量 → 渲染 → 效果不对回改）→ 新流程（编辑器内插入变量 + 实时预览）→ **成本差异在哪** |
| 首屏 **LCP 1.3s** | "怎么优化的？基线是多少？" | 优化手段（代码分割 / 资源预加载 / 图片 / 缓存）+ **优化前的数值** |
| 交付周期**缩短 50%+** | "怎么算的？" | 举具体例子："原本 X 人天的功能，现在 Y 天完成"（准备 1-2 个） |
| 从 0 到 1 搭建中台（3 人） | "团队怎么分工的？" | 你的角色 + 分工方式 + 交付节奏 |
| **覆盖贷款全生命周期** | "原来是什么范围？" | 原来仅贷后阶段 → 抽离为公共模块后全生命周期可用 |
| 技术知识库 200+ 篇 | "都写什么内容？" | 分类说明（JS 原理 / 框架源码 / 工程化 / 后端 / AI）+ **为什么要写** |
| AI 应用实践（3 个项目） | 见第二节，逐个深挖 | 每个项目的技术选型 + 实现细节 + 遇到的难点 |

> **原则**：简历上出现的每个数字，都要能**当场展开 30 秒的细节**。做不到的就从简历里删掉。

## 二、个人项目深挖（简历新增，必问）

这三个项目是你和其他 10 年前端**最大的差异点**，也是面试官最可能深挖的地方。

### 2.1 RAG 知识库问答系统

**一句话介绍**（背下来）：

> "我把自己的技术知识库（200+ 篇文档）做成了一个可以自然语言问答的系统——后端用 Koa + TS，文档经语义切分后向量化存进 Chroma，检索到相关内容后交给本地部署的 qwen3 模型生成回答，通过 SSE 流式推给前端。后来把单轮检索升级成了 Agent 工具调用循环，支持多轮检索和追问。"

**技术追问准备**：

| 追问 | 回答要点 |
|------|---------|
| **为什么用 RAG 不用微调？** | ① 知识库持续更新，微调成本高、更新慢；② 微调容易灾难性遗忘；③ RAG 可溯源（回答能给出处），微调不能 |
| **为什么用本地模型（Ollama）？** | ① 零 API 成本；② 数据不出本机（个人知识库有隐私性）；③ 顺便学习模型部署。代价是能力弱于云端模型，但对"检索 + 总结"这个场景够用 |
| **文档怎么切分的？** | 按 Markdown 结构切（标题层级 + 段落），而不是固定字数——**保持语义完整**比切得均匀更重要；代码块不切碎 |
| **为什么选 Chroma？** | 轻量、嵌入式、支持持久化到本地目录，适合单机场景；生产环境会考虑 Milvus / pgvector |
| **embedding 用的什么？** | bge-m3（中文效果好的开源 embedding 模型），通过 Ollama 提供 |
| **怎么评估检索效果？** | 准备一组"问题 → 期望命中文档"的测试集，人工看 top-k 命中率（诚实说：个人项目没做严谨评估，靠抽样验证） |
| **Agent 工具调用怎么实现的？** | 定义了两个工具（`search_knowledge` 检索、`get_doc_content` 取全文），模型返回 `tool_calls` 后执行工具、把结果回传，循环直到模型不再调用工具（有最大轮次保护） |
| **怎么减少幻觉？** | ① 检索结果作为上下文强约束（"只根据以下资料回答"）；② 回答带来源引用，用户可验证；③ 检索不到时明确说"没找到相关内容"而不是编 |
| **流式怎么做的？** | 后端 SSE（`text/event-stream`）逐块推送，前端 EventSource / fetch stream 接收并实时渲染 |

### 2.2 DevAgent Harness · AI 开发工作流工具箱

**一句话介绍**：

> "AI 辅助开发有个通病：直接让 AI 写代码，它可能跳过设计、上下文给太多浪费 token、踩过的坑下次还踩。我设计了一套工作流框架来约束它——把开发拆成固定阶段（设计→计划→实施→测试→审查→复盘），每个阶段有明确的输入输出和门禁，AI 不能跳步；同时按阶段只加载需要的上下文，踩坑记录沉淀成知识库，下次同类任务自动带上。"

**技术追问准备**：

| 追问 | 回答要点 |
|------|---------|
| **和 Cursor / Copilot 什么关系？** | 不是竞品，是**上层流程**。Cursor 解决"AI 怎么写代码"，Harness 解决"AI 按什么流程写、怎么保证质量可复现"。可以理解为给 AI 加了一套工程规范 |
| **为什么做两层架构（通用层 + 项目层）？** | 通用层沉淀"所有项目都适用"的工作流模板和 Skill 规范；项目层放项目特定的命令、规范、经验。通过 git submodule 嵌入 → **框架可复用，项目可定制**，升级框架不影响项目数据 |
| **"门禁"怎么实现的？** | 每个阶段定义产出物要求（必须生成哪些文件、包含哪些 section），进入下一阶段前检查产出是否完整；关键阶段需要用户确认才继续 |
| **"经验闭环"怎么落地？** | 复盘阶段自动生成草稿 → 人工确认后写入 `knowledge/lessons/` → 下次同类任务启动时按索引加载相关经验 |
| **"精准上下文"具体怎么做的？** | 用 `context-rules/` 定义"哪个阶段需要加载哪些文件/skill"，避免一次性把所有规则塞进 prompt（token 消耗大且干扰判断） |
| **实际效果如何？** | 交付周期缩短 50%+（举具体例子）；更重要的是**产出可复现**——同类任务的质量稳定，不依赖"这次 prompt 写得好不好" |
| **6 种工作流怎么选？** | feature（新功能/重构）、bugfix（修 bug）、requirements（需求脑暴）、project-init（从零搭项目）、skill-creation（造技能）、workflow-creation（造工作流） |

### 2.3 Agent CLI · 终端 AI 编程助手

**一句话介绍**：

> "为了真正理解 Agent 的运行时原理，我从 0 写了一个命令行 AI Agent——包含 Agent 循环、工具系统、会话管理和终端 TUI 渲染，并配了单元测试和终端模拟的 e2e 测试。它现在还比较简陋，但把'流式响应怎么解析、工具调用怎么累积、多轮上下文怎么维护'这些机制跑通了一遍。"

> ⚠️ **诚实定位**：这个项目你自己也说"做得还不太好"，所以**主动承认它的局限**（"还比较简陋"）反而加分——体现你知道差距在哪，而不是吹。

**技术追问准备**：

| 追问 | 回答要点 |
|------|---------|
| **Agent 循环的核心逻辑？** | 发消息 → 流式接收响应 → 解析出 `tool_calls`（delta 增量累积，要拼接完整）→ 执行工具 → 把结果作为新消息回传 → 循环直到无工具调用 |
| **工具调用怎么设计的？** | 工具用 JSON Schema 声明参数（name / description / parameters），注册到工具表；模型返回调用意图后按 name 查找并执行 |
| **为什么要做终端模拟测试？** | TUI 渲染难以用普通单元测试验证，所以模拟终端输入输出做 e2e 断言（测试交互流程而不只是函数返回值） |
| **和 RAG 项目里的 Agent 有什么区别？** | RAG 里的 Agent 是"业务内嵌的工具调用"（只读知识库）；CLI 是"通用 Agent 运行时"（工具可扩展、有会话和 UI 层） |

## 五、技术复习清单

### 5.1 必背（几乎每场都问）

**JavaScript 核心**：
- 闭包 / 作用域链 / 变量提升
- 原型链与继承（`__proto__` vs `prototype`）
- 事件循环（宏任务 / 微任务、`await` 的调度）
- `this` 绑定规则（4 种 + 箭头函数）
- 手写题：Promise（含 `all` / `allSettled` / `race` / `any`）、防抖节流、深拷贝、并发控制、`instanceof`

> 📌 你的知识库 `javascript/` 目录下有完整整理，面试前重点刷：`closure.md`、`event-loop.md`、`async.md`、`async-concurrency.md`

**React**：
- Fiber 架构（为什么需要、时间切片）
- Hooks 原理（闭包陷阱、依赖数组、`useState` 的批量更新）
- diff 算法与 key
- 状态管理选型

**Vue**：
- 响应式原理（`Object.defineProperty` vs `Proxy`）
- diff 算法（双端比较）
- 生命周期与 `nextTick`

**浏览器 / 网络**：
- 从输入 URL 到页面渲染
- 缓存策略（强缓存 / 协商缓存）
- 跨域方案（CORS / 代理 / JSONP）
- HTTP 1.1 / 2 / 3 差异

**性能优化**：
- 首屏优化手段（代码分割、预加载、SSR、CDN）
- 运行时优化（长列表、防抖节流、内存泄漏）
- 指标：LCP / FCP / CLS / TTI

### 5.2 全栈岗加考

- **Node**：事件循环（与浏览器差异）、Stream、Cluster、Koa 中间件（洋葱模型）
- **数据库**：索引原理（B+ 树）、事务与隔离级别、MVCC、慢查询优化
- **Redis**：数据类型与场景、缓存三兄弟（穿透 / 击穿 / 雪崩）、分布式锁
- **部署**：Docker 基础、nginx 反代、CI/CD 流程

> 📌 对应知识库：`service/mysql-advanced.md`、`service/database.md`、`service/redis-intro.md`、`service/docker.md`、`service/node-deployment.md`

### 5.3 AI 方向（差异化加分，不用怕被问）

- RAG 原理（检索 → 增强 → 生成）与适用边界
- 向量检索（embedding、相似度、chunk 策略）
- Agent 与工具调用（Function Calling 机制）
- Prompt 工程（结构化约束、Few-shot）
- LLM 应用常见问题（幻觉、上下文长度、成本控制）

> 📌 对应知识库：`ai-agent/rag/knowledge-base.md`、`ai-agent/` 目录

## 六、薪资谈判

**你的底线**：18K（低于这个不接）

**报价策略**：

| 步骤 | 做法 | 话术 |
|------|------|------|
| 1 | **先问对方预算**（不要先报数字） | "想先了解一下这个岗位的薪资范围大概是怎样的？" |
