# 领导面准备文档（大模型中转站 · 全栈工程师）

> 适用：已过第一轮技术面，剩余两轮领导面（大概率一轮技术总监/业务负责人，一轮 VP/老板/HR 老大）
> 公司业务：大模型中转站（聚合多家 LLM API，统一接口对外售卖调用量）
> 技术栈：前端 Vue、后端 Java
> 更新日期：2026-08-17

---

## 零、领导面到底考什么（先建立认知框架）

技术面考「你会不会」，领导面考「**你是谁、你值不值、你能不能扛事**」。四个维度：

1. **业务理解**——能不能听懂他们的生意，甚至帮他们想清楚问题
2. **判断力与视野**——面对复杂问题怎么权衡，而不是背答案
3. **软素质**——沟通、抗压、冲突处理、跨团队推动
4. **稳定与动机**——为什么是你、为什么是现在、来了能不能干得久

领导面解决的是**信任问题**：把团队或模块交给你，放不放心。

## 一、大模型中转站业务认知（必背）

### 一句话讲清业务

> 上游聚合多家大模型厂商（OpenAI / Claude / DeepSeek / 通义 / 文心等），下游以统一的 OpenAI 兼容接口卖给开发者和企业，赚的是 API 调用差价 + 增值服务（私有化、定制、SLA）的钱。

### 全链路技术地图（做到能脱口而出）

| 环节 | 技术本质 | 对应已有经验 |
|---|---|---|
| 模型接入与路由 | 多上游适配、按模型/成本/可用性路由 | RAG 里的多模型切换 |
| API 转发网关 | 高并发代理、SSE 流式转发、协议转换 | LLM 流式渲染（懂 SSE 消费端） |
| 计费计量 | 按 token 计费、余额、账单、充值、扣费 | 金融 SaaS 的账单/合规经验 |
| 限流熔断降级 | 上游限流、多租户配额 | BFF 层治理经验可迁移 |
| 多租户 / Key 管理 | API Key 生命周期、权限、审计 | 客服平台权限/SSO 经验 |
| 前端控制台 | 用量图表、Key 管理、Playground、文档站 | 强项 |

### 必答题：「为什么不直接用开源的 one-api / new-api？」

> 开源方案解决了「能用」，但企业级中转站的核心壁垒在**计费准确性、成本控制、SLA 稳定性、私有化交付**——这些恰恰是开源项目最弱的地方，也是公司存在的理由。

### 增值层（面试官眼睛会亮的地方）

中转站是「管道」，管道之上要做应用才能放大价值：
- RAG / 知识库方案（我有完整落地经验）
- Agent 编排
- 企业私有化部署
- Playground / 调试台 / 文档站等开发者体验

## 二、价值主张：为什么公司需要「你」

别讲「我什么都会」，讲**你是来补哪块板子的**：

1. **AI 应用层经验**——中转站之上要做 RAG、Agent、私有化增值服务。我有完整 RAG 知识库落地（向量检索→LLM 对话→流式渲染），纯后端候选人没有
2. **前端体验 + 开发者体验（DX）**——控制台、Playground、文档站是开发者第一印象，直接影响付费转化。这是纯后端团队最不擅长的
3. **AI 辅助开发工程化**——设计过「Prompt 约束 + 多 Agent 编排 + Skill 沉淀」完整工作流。公司全员跟大模型打交道，我能把「用 AI 提效研发」从口号变成体系

### 一句话定位（背下来）

> 我不只是前端，我是在 AI 全栈这条线上，能同时把应用层体验、工程化效率和中转站之上的增值服务扛起来的人。

## 三、高危问题与应答策略（重点准备 5 个）

### 1. 「我们后端是 Java，你行不行？」——答不好直接出局

给**路径**而不是表态：
- 信息安全专业出身，大学体系里 Java 是基本功，不是零基础
- Node 和 Java 在服务端抽象层面（网络、并发、存储、中间件）完全相通，缺的只是语言熟练度，不是服务端思维
- 已验证过两次技术栈迁移：JS→TS、Vue→React 全量迁移，学习曲线没问题
- 收尾承诺：入职前系统过一遍 Java 生态（Spring Boot + 常见中间件），入职 1 个月内能独立干活

**禁区：**「我是前端的，Java 不熟」——领导面说这句等于自我淘汰。

### 2. 「我们前端是 Vue，你是 React 为主」

- 两个都精通（简历明确写了精通 React、Vue），有 Vue + Webpack + iView 后台、uni-app 小程序实战
- 更值钱的是跨框架架构能力（微前端、Monorepo、组件库体系），框架只是工具

### 3. 「你 10 年经验，为什么不去做纯管理？」

- 定位是**技术型全栈，管理是附带能力**：团队小的时候亲自下场写代码 + 带人
- 众安带团队、跨团队协调经验是「技术 Leader」型而非「纯 Manager」型——对技术驱动的创业公司，这种形态通常更受欢迎

### 4. 「为什么离开上家 / 为什么看我们？」

- 主线：众安出来是主动求变（大厂稳定但创新空间小），去蜜獾是 AI 方向转型，现在明确把**职业锚点定在 AI 全栈**
- 选这家公司的理由要具体：**业务在 AI 基础设施黄金赛道 + 全栈岗位能发挥综合能力 + 看重成长空间**
- 禁区：只说「离家近/钱多」，领导最反感没有业务热情

### 5. 「全栈是你的定位还是包装？」

- 用事实说话：独立搭过 RAG 知识库**完整链路**（Koa 服务端、Chroma 向量库、索引构建），这是真全栈
- 诚实承认边界：后端强在应用层与 BFF，高并发网关、分布式计费这类重型后端需要借助公司现有架构学习
- **诚实 + 可成长**是领导面最安全的姿态

## 四、两轮领导面的不同打法

### 第一轮（技术总监/业务负责人）：考判断力
- 深挖项目决策过程：为什么微前端、为什么自研编辑器、为什么 RAG 用这个方案——**讲权衡（代价）而不是讲结果**
- 试探怎么带人、怎么定技术方案、怎么跟产品协作
- 复用 `interview-questions/2026-08-14-architect.md` 的练习：约束/边界/权衡/可逆性那套语言就是他们想听的

### 第二轮（VP/老板/HR 老大）：考人和动机
- 聊职业规划、稳定性、价值观、期望薪资
- 观察**气场和沟通方式**：中转站是 to B 生意，谈吐就是产品形象
- 准备 30 秒和 2 分钟两个版本自我介绍，后者带「AI 全栈」主线

## 五、STAR 故事弹药库（每个 1-2 分钟，四段式：背景→决策→行动→结果+量化）

| 场景 | 故事 | 亮点 |
|---|---|---|
| 架构决策 | 客服平台微前端：5+ 子应用、存量系统渐进改造 | 权衡思维、跨团队推动 |
| 攻坚 | 模板编辑器 0→1：Command 模式 + 撤销重做 + AI 协作攻坚 | 从 0 到 1、技术选型 |
| AI 落地 | 设计 Prompt 约束的多阶段 Agent 工作流 + Skill 沉淀 | 对 AI 有工程化理解（**最稀缺，重点讲**） |
| 管理 | 众安带团队 + 跨团队协调 + 项目两年获奖 | Leader 素质 |
| 抗压 | 技威时代一年用户量 +1000 万、收益超 1000 万 | 业务结果导向 |

准备方法：每个故事先自己讲一遍并计时，控制在 1-2 分钟。

## 六、反问问题（领导面必问「你有什么想问的」，也是加分题）

- **业务向**：「模型价格战打这么凶，咱们在成本控制和利润结构上怎么应对？自研网关和开源方案（one-api）的边界在哪里？」
- **战略向**：「除了 API 转售，公司在 RAG / Agent / 私有化这些增值层上有什么规划？」——正好是强项，会让他们眼睛一亮
- **团队向**：「这个岗位进来是补前端，还是全栈链路都要扛？团队现在的构成和节奏？」

最后一个问题一定落到团队/岗位，显示已经在想怎么干活了。

## 七、临场提醒

1. **控制语速**：领导面问题开放性大，答 1-2 分钟即可，给面试官追问空间，别自我表演
2. **全程带业务视角**：讲任何技术都往「对公司生意有什么用」上收
3. **别迟到**：提前 15 分钟进会议，设备/网络先测好
