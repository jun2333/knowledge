# Node.js 高并发与高可用设计

> **优先级：P1** — 理解 Node 能扛并发的前提（单线程事件循环），再谈"怎么设计让它高并发高可用"。本文不背代码，讲**设计决策**。

## 一、先理解 Node 的并发模型（为什么它能扛 IO 密集）

Node 是**单线程事件循环 + 异步 IO**：

```
主线程（一个）
  ├─ 请求进来 → 注册回调（不等待）→ 处理下一个
  ├─ IO 完成（DB/网络/文件）→ 事件循环唤醒回调 → 续上
  └─ 单个慢请求不阻塞其他请求（await 只挂起"当前逻辑流"）
```

**优势**：IO 密集场景下，一个进程能同时挂几万个等待中的请求，内存占用远小于"每请求一线程"的 Java。

**短板**：纯 CPU 计算（JSON 大解析、加密、图像处理）会**阻塞事件循环**——期间所有请求卡住。

> **高并发的第一原则**：把 CPU 密集工作挪出主线程（worker_threads / 拆到别的服务 / MQ）。

## 二、高并发设计（单机怎么扛更多）

| 手段 | 做什么 | 解决什么 |
|------|--------|---------|
| **全程异步 IO** | 用 fs/promises、`await` 数据库，**绝不调阻塞版 API**（如 `readFileSync`） | 别自己堵死事件循环 |
| **cluster 多进程** | 起 N 个 worker 进程吃满多核（Node 单进程只用一个核） | 单核 → 多核 |
| **worker_threads** | CPU 密集任务丢线程池 | 主线程不被计算卡住 |
| **PM2 fork 模式** | `pm2 start app.js -i max`（多实例 + 自动重启） | 多核 + 进程守护 |
| **nginx 反代前置** | 静态资源 nginx 直接吐、动态走 Node | 减少 Node 负担 + keepalive |

**为什么 nginx 前置**：Node 不擅长静态文件/连接管理，nginx（C 写的、事件模型更极致）在前面挡静态 + 负载均衡，Node 专注业务。

## 三、高可用设计（挂了/多了也不出事）

```
无状态化：session/token 外置（Redis）→ 任何实例都能接任何请求
         （这是"能水平扩展"的前提）
负载均衡：nginx / 云 LB 分发到多实例 + 健康检查（自动摘掉挂的）
进程守护：PM2/cluster 崩溃自动重启（单点进程挂了能自愈）
超时/熔断：外部调用设超时 + 熔断降级（依赖挂了给兜底，别连锁崩）
日志监控：请求日志（ELK/Sentry）+ 健康检查端点
```

**核心认知**：单实例再优化也有上限，**高可用 = 多实例 + 无状态 + 自动摘除 + 自愈**。

## 四、什么时候不该硬扛（识别瓶颈）

```
CPU 密集重负载（视频转码/大规模计算） → Node 不合适，交给 Go/Rust/专用服务
复杂事务/强一致性业务 → 数据库才是瓶颈，语言救不了
如果 QPS 高但都是 IO（查缓存/查库）→ Node 合适，先看 DB/Redis 扛不扛得住
```

## 五、实践清单

| 清单项 | 说明 |
|--------|------|
| 别用阻塞 API | 同步读文件等 = 自杀式写法 |
| 请求进 Node 前先挡一层 | nginx 静态 + 限流 + 负载均衡 |
| 多核用 cluster/PM2 -i | 单进程只吃一个核是浪费 |
| CPU 任务丢 worker | 别让计算堵死主线程 |
| 无状态化 | session 外置，实例才能随便扩 |
| 进程守护 | 崩溃自愈（PM2/集群） |
| 外部依赖熔断 | 超时 + 降级，防连锁雪崩 |
| 监控前置 | 日志/指标先上线，出事能定位 |

## 一句话

> Node 高并发的底气是**单线程事件循环**（IO 密集省资源），设计关键：**异步到底 + 多进程吃满核 + CPU 任务挪走 + 无状态多实例 + 进程守护**；高可用靠"多实例 + 负载均衡 + 自愈"，不是单进程硬扛。**识别短板**（CPU 密集）比堆优化更重要——瓶颈在 DB 或计算时，先解决那里。
