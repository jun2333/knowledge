# JVM 入门

> **优先级：P0（面试必考）** — JVM 与并发并称 Java 面试两大护城河，几乎必问。

::: tip 背景
JS 开发者不需要关心 V8 内存细节也能干活；但 Java 面试会把 JVM 内存模型、GC、类加载当基础题问。本文聚焦面试考点，不深入源码。
:::

## JVM 是什么

Java 程序运行在 JVM（Java Virtual Machine）上：`.java` 编译为 `.class` 字节码，JVM 解释/编译执行。**一次编译，到处运行** 靠的就是 JVM 屏蔽了操作系统差异。

```
.java --javac--> .class --JVM--> 机器码
```

## 内存分区（必考，画图题）

```
┌─────────────────────────────────────┐
│ 线程共享                              │
│  ┌──────────┬──────────┬──────────┐  │
│  │  堆 Heap  │ 方法区/元空间 │  直接内存 │  │
│  │ (对象实例) │ (类信息/常量) │ (NIO)    │  │
│  └──────────┴──────────┴──────────┘  │
├─────────────────────────────────────┤
│ 线程私有                              │
│  ┌──────────┬──────────┬──────────┐  │
│  │ 虚拟机栈    │ 本地方法栈 │ 程序计数器 │  │
│  │ (方法调用) │ (native) │ (下一条指令)│  │
│  └──────────┴──────────┴──────────┘  │
└─────────────────────────────────────┘
```

| 区域 | 存什么 | 线程 | 异常 |
|------|--------|------|------|
| **堆** | 所有对象实例、数组 | 共享 | `OutOfMemoryError: Java heap space` |
| **方法区/元空间** | 类信息、常量、静态变量（JDK 8+ 用元空间，本地内存） | 共享 | `OOM: Metaspace` |
| **虚拟机栈** | 每个方法一个栈帧（局部变量、操作数栈） | 私有 | `StackOverflowError`（递归过深） |
| **程序计数器** | 当前执行指令地址 | 私有 | 无 |
| **直接内存** | NIO 的堆外内存 | 共享 | `OOM: Direct buffer memory` |

**JDK 8 变化**：永久代（PermGen）→ 元空间（Metaspace），从堆内移到了本地内存，不再有 PermGen OOM。

## 垃圾回收（GC）

### 判断对象可回收

- **引用计数法**（早期）：循环引用问题，已弃用
- **可达性分析**（现用）：从 GC Roots 出发遍历，不可达即垃圾。GC Roots 包括：栈帧局部变量、静态变量、JNI 引用、活跃线程

### 回收算法

| 算法 | 思路 | 缺点 |
|------|------|------|
| **标记-清除** | 标记垃圾后直接清除 | 内存碎片 |
| **标记-复制** | 存活对象复制到另一半区域 | 浪费一半空间；适合"存活少"（新生代） |
| **标记-整理** | 存活对象移到一端，清掉其余 | 移动成本高；适合"存活多"（老年代） |

### 分代收集

```
新生代（复制算法，Minor GC 频繁）
├── Eden（新对象）
└── Survivor S0 / S1（幸存者，年龄 +1，15 岁进老年代）
老年代（标记-整理/标记-清除，Major GC）
```

**为什么分代**：绝大多数对象朝生夕灭（如方法里的临时对象），新生代用复制算法性价比最高。

### 常见收集器（面试答 G1 即可）

| 收集器 | 特点 |
|--------|------|
| **G1**（JDK 9+ 默认） | 分 Region 管理堆，可预测停顿时间（`-XX:MaxGCPauseMillis`），JDK 17 默认 |
| ZGC | JDK 15+，超低停顿（毫秒级），适合超大堆 |
| CMS | 老牌并发收集器，已废弃（JDK 14+ 移除） |

G1 一句话：**把堆分成多个 Region，优先回收垃圾最多的 Region**（Garbage First 名字由来）。

## 类加载机制

### 生命周期

```
加载 → 验证 → 准备 → 解析 → 初始化 → 使用 → 卸载
```

- **加载**：读 .class 文件生成 Class 对象
- **验证**：字节码安全校验
- **准备**：静态变量赋默认值（0 / null）
- **解析**：符号引用 → 直接引用
- **初始化**：执行静态代码块、静态变量赋真实值

### 双亲委派模型（必考）

```
启动类加载器 Bootstrap（rt.jar，JDK 核心类）
  ↑ 委托
扩展类加载器 Platform（JDK 扩展类）
  ↑ 委托
应用类加载器 App（classpath 下的类）
```

**流程**：类加载请求 → 先问父加载器能不能加载 → 父都不行才自己加载。

**为什么这样设计**：保证核心类安全——你的代码无法覆盖 `java.lang.String`，避免污染 JDK 核心类（核心类始终由 Bootstrap 加载）。

**打破双亲委派**：SPI（JDBC 等）用线程上下文类加载器，Tomcat 也打破了（每个应用隔离）。

## JVM 调优与排查（面试基础）

常用参数：

```
-Xms256m -Xmx256m        # 堆初始/最大（生产建议相等，避免扩容抖动）
-Xss512k                 # 每个线程栈大小
-XX:MaxMetaspaceSize     # 元空间上限
-XX:+HeapDumpOnOutOfMemoryError   # OOM 时自动 dump
```

排查命令（详见 [线上问题排查](/service/troubleshooting)）：

```
jps       # 查看 Java 进程
jstack    # 线程栈（查死锁、线程状态）
jmap      # 堆快照（查 OOM 对象）
jstat     # 查看 GC 频率与耗时
```

## 面试题速查

| 问题 | 一句话答案 |
|------|-----------|
| 堆和栈的区别 | 堆存对象（共享）、栈存调用帧（私有）；堆要 GC、栈随方法退出自动释放 |
| 什么是 OOM | 堆/元空间/直接内存耗尽的 `OutOfMemoryError` |
| 什么是 StackOverflow | 栈深度超限，递归没出口 |
| GC 判断对象死亡的算法 | 可达性分析（GC Roots） |
| 新生代为什么用复制算法 | 存活少，复制成本低、无碎片 |
| G1 和 CMS 区别 | G1 分 Region、可预测停顿；CMS 已废弃 |
| 双亲委派是什么 | 子加载器先委托父加载器，保证核心类不被覆盖 |
| 什么时候触发 Full GC | 老年代空间不足、元空间不足、System.gc() |
