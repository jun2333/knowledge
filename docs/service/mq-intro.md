# 消息队列（Kafka）入门

> **优先级：P1（中高级岗必问）** — 核心三问：为什么用 MQ、消息怎么不丢、怎么不重复消费。

::: tip 背景
消息队列（MQ）用于系统间异步通信、削峰填谷、解耦。主流：Kafka（大数据量、日志）、RabbitMQ（业务消息）、RocketMQ（阿里系，业务消息+事务）。本文以 Kafka 为主讲通用概念。
:::

## 为什么用 MQ（三个核心价值，必答）

| 价值 | 场景 | 不用 MQ 的问题 |
|------|------|---------------|
| **异步** | 下单后发短信/通知，不用等 | 同步调用链路长，响应慢 |
| **削峰填谷** | 秒杀/大促瞬间流量打 DB | 数据库直接被冲垮 |
| **解耦** | 订单系统和库存系统通过消息通信 | 强耦合，改一个全改 |

```
同步调用：订单 → 短信 → 库存 → 积分（串行，全等）
MQ 异步：订单 → MQ →（短信/库存/积分各自消费）
```

**面试题：为什么引入 MQ 而不直接异步线程？**——MQ 是跨系统、可持久化、可重试、可追溯的可靠异步；进程内线程只能处理单机。

## Kafka 核心概念

```
Producer（生产者）
   ↓ 发送消息
Topic（主题 = 消息分类）
   ├── Partition 0 ──> Consumer Group A（组内分摊消费）
   ├── Partition 1 ──> Consumer Group A
   └── Partition 2 ──> Consumer Group B（不同组各消费一份）
```

| 概念 | 说明 |
|------|------|
| **Topic** | 消息分类（对应表） |
| **Partition** | Topic 的分片（顺序写 + 并行消费的基础，一个分区内消息有序） |
| **Consumer Group** | 组内消费者分摊分区（一条消息组内只消费一次）；**不同组各消费一遍** |
| Offset | 分区内消息的消费位置（对应游标） |
| Broker | Kafka 节点（集群） |

**顺序性保证**：同一个 key（如订单 id）的消息进同一个分区 → 分区内有序 → 消费者按序处理。**Kafka 只保证分区内有序，不保证跨分区有序**。

## 消息可靠性（面试核心：怎么不丢消息）

消息丢了 = 生产者丢 / Broker 丢 / 消费者丢，三段分别防：

| 阶段 | 丢失原因 | 解决 |
|------|---------|------|
| **生产者 → Broker** | 发送失败未确认 | `acks = all`（等待所有副本确认）+ 重试机制 |
| **Broker 存** | 宕机内存数据丢 | 副本机制：`replication-factor = 3`（多副本） |
| **Broker → 消费者** | 先提交 offset 再处理，处理中挂了 | **先处理业务再提交 offset**（手动提交） |

**必考题：消费者怎么保证不丢？**——禁止自动提交 offset；业务处理成功后再手动 `commitSync()`。代价是可能重复消费（见下）。

## 重复消费与幂等（面试核心：怎么不多消费）

**为什么必然可能重复**：消费者处理完但还没来得及提交 offset 就挂了 → 重启后重新消费同一批消息。

**解决思路：消费端幂等**（不指望 MQ 去重，业务自己扛）：

1. **唯一键 + 数据库去重**：消息带唯一业务 id（如 orderId），消费时 `INSERT IGNORE` / 查重
2. **状态机校验**：订单已支付就不再重复支付（状态字段判断）
3. **Redis 幂等**：`SETNX` 业务 id，已存在则跳过

**面试答题结构**：MQ 天然 at-least-once（至少一次）→ 必然可能重复 → 靠业务幂等兜底（唯一键/状态机）。

## 消息顺序问题

| 场景 | 方案 |
|------|------|
| 全局有序 | 1 个分区 + 1 个消费者（牺牲吞吐，基本不用） |
| 部分有序（常用） | 按业务 key 分区（如订单号 hash），单分区内有序 + 单消费者线程 |

**面试题：消息乱序怎么处理？**——回答：按 key 分区保证同 key 有序；消费者侧可以加序号比对（消息带递增序号，乱序则等待）。

## 延迟队列 / 死信队列（RocketMQ 特色，加分项）

- **延迟消息**：订单 30 分钟未支付自动关闭——发延迟消息，30 分钟后消费
- **死信队列（DLQ）**：消费失败多次的消息进死信队列，人工排查（对应你的重试机制）

## 面试题速查

| 问题 | 一句话答案 |
|------|-----------|
| MQ 三个价值 | 异步、削峰、解耦 |
| Kafka 怎么保证有序 | 同 key 同分区，分区内有序 |
| 消息丢失怎么防 | acks=all + 副本 + 手动提交 offset |
| 重复消费怎么处理 | 幂等：唯一键去重 / 状态机 |
| 为什么会有重复消费 | 处理完没提交 offset 就挂了，重放 |
| 分区和消费组 | 分区内有序；组内分摊、组间各消费一遍 |
| 消息积压怎么办 | 扩分区 + 扩消费者（消费能力对齐分区数）；紧急时临时转储 |
