# RAG vs 微调（Fine-tuning）

> 面试高频题："你的知识库为什么用 RAG 不用微调？"
> 本文先把**微调**讲透，再回答这个问题。RAG 本身见 [RAG 入门](./introduction.md)。

## 一、微调（Fine-tuning）是什么

**一句话**：拿一个已经预训练好的大模型，用你自己的数据**继续训练**，去改动它的参数（权重），让它更贴合你的任务或领域。

关键在"改动参数"——微调之后，**模型本身变了**。你喂给它的知识或风格，被"烧"进了那几十亿个参数里。

### 一个类比：闭卷考试 vs 开卷考试

| | 微调（Fine-tuning） | RAG（检索增强） |
|---|---------------------|-----------------|
| 类比 | **闭卷考试** | **开卷考试** |
| 知识在哪 | 模型"脑子"里（参数） | 外部资料库（向量库） |
| 模型变不变 | **变**（权重被改写） | **不变**（模型原封不动） |
| 加/换知识 | 重新训练 | 重建索引 |
| 能否说出出处 | 不能 | 能（引用来源） |

`qwen3:8b` 微调，就是拿你的数据再喂给它、跑一轮训练，把"你的东西"刻进那 80 亿个参数里。

### 微调的主要类型

| 类型 | 说明 | 成本 |
|------|------|------|
| **全量微调（Full FT）** | 更新模型所有参数 | 最高，通常要多卡 GPU |
| **LoRA / QLoRA（PEFT）** | 冻结原模型，只训练一小撮附加参数 | 低，个人显卡可玩 |
| **SFT（指令微调）** | 用"指令 → 回答"成对数据，教模型怎么答 | 中 |
| **RLHF / DPO** | 用人类偏好数据对齐模型的"口味" | 高 |

> 记忆点：**微调擅长教"怎么答"（风格、格式、领域黑话、指令遵循），不擅长注入"答什么"（频繁变动的事实知识）。**

## 二、RAG 和微调解决的不是同一个问题

- **RAG 管"答什么"**：知识放在外部，回答时现查现用（检索 → 增强 → 生成）。
- **微调管"怎么答"**：把风格、格式、领域表达习惯训练进模型。

所以两者不是替代关系。先想清楚你的目标是"让模型记住具体知识"还是"改变模型的表达方式"。

## 三、RAG vs 微调 对比

| 维度 | RAG | 微调（Fine-tuning） |
|------|-----|---------------------|
| 知识更新 | 实时（重建索引即可） | 需重新训练，慢且贵 |
| 成本 | 低（只做 embedding + 检索） | 高（训练需 GPU、数据标注） |
| 数据量要求 | 低（几篇文档就能用） | 高（需大量高质量样本） |
| 可解释性 | 可追溯来源 | 黑盒，说不出出处 |
| 幻觉控制 | 较好（原文强约束） | 仍有幻觉，甚至更"自信" |
| 灾难性遗忘 | 无（模型不变） | 有风险（覆盖原有能力） |
| 隐私/可控 | 数据在向量库，可精确增删 | 知识融进参数，难以"删干净" |
| 擅长 | 动态知识、问答、检索 | 风格迁移、格式固定、领域术语 |

## 四、为什么"知识库问答"用 RAG 不用微调

结合本项目（Koa + TS，Chroma 向量库，本地 Ollama 部署 `qwen3:8b` + `bge-m3`）：

1. **知识持续更新**：知识库还在不断加文章。RAG 只需重跑一次 `pnpm kb index` 重建索引，分钟级；微调要重新准备数据 + 重新训练，慢且贵。
2. **成本与资源**：微调 `qwen3:8b` 需要 GPU 显存和大量数据；本项目用本地 Ollama + Chroma，消费级机器即可跑。
3. **数据量不够**：微调需要大量高质量"问题-答案"样本，个人知识库这点量很容易过拟合；RAG 对样本量要求低。
4. **可溯源（面试最爱追问）**：RAG 能给出"这段来自哪篇文档"，用户可点开源文验证；微调把知识混进参数，答出来也说不出出处。
5. **抗幻觉**：RAG 用检索到的原文做强约束（"只根据以下资料回答"）；微调模型容易"自信地胡说"。
6. **灾难性遗忘**：微调会覆盖模型原有的通用能力，"学新的忘旧的"；RAG 完全不动模型，通用能力原样保留。
7. **可控可删除**：RAG 里删掉某篇文档，检索立刻搜不到；微调进参数的知识，几乎无法"删干净"。

## 五、进阶：什么时候才需要微调

不是说微调没用，而是它解决的是另一类问题：

- **固定输出风格/格式**：要求模型始终按某模板、始终带引用格式输出。
- **领域黑话理解**：让模型更懂某行业/公司内部的术语与表达。
- **提升检索质量**：微调 embedding 模型或 reranker，让"检索得更准"。
- **组合打法**：**RAG 供给知识 + 微调约束风格**——这是很多生产系统的实际做法。

## 六、面试速答版（30 秒）

> "RAG 和微调解决的不是同一个问题——RAG 管'答什么'（知识），微调管'怎么答'（风格、格式、领域术语）。我的知识库持续更新、数据量不大、又要求回答能给出处，这几个点正好都是 RAG 的强项、微调的短板（更新要重训、成本高、易灾难性遗忘、不可溯源），所以我选 RAG。真要提升，我会用微调 LoRA 去优化输出格式或微调 reranker 提升检索，而不是拿它来存知识。"
