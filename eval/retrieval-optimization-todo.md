# 检索优化记录

> 记录「文档确实讲了、但检索没捞到」的题，以及实测出来的根因与解法。
> 每次改动后跑 `pnpm test:rag` 对比基线确认效果。

## 结论（2026-09-24）

**全部 5 条已解决**：#1~#4 由**混合检索（向量 + BM25）**解决，#5 由放宽 `expect` 解决。
`kb cases:review` 现在输出 **0 条 A 类（未命中）/ 0 条 B 类（相似度偏低）**。

| 指标 | 优化前（纯向量） | 优化后（混合检索） |
|---|---|---|
| Hit@5 | 98.4% | **100.0%** |
| Hit@1 | 87.6% | **90.0%** |
| Recall@5 | 0.964 | **0.985** |
| MRR | 0.923 | **0.944** |

成本：**零模型、微秒级**（BM25 是纯算法，语料在内存里建索引）。

## 混合检索为什么有效

纯向量在**精确词**上最弱——英文缩写、专有名词、代码标识符这类内容在向量空间里容易和无关文档"漂"到一起。而下面这些失败题**全都带精确词**：

| # | 题 | 期望文档 | 文档里的精确词 |
|---|---|---|---|
| 1 | FMP和LCP有什么区别？ | `performance/metrics.md` | `FMP（First Meaningful Paint）` / `LCP` |
| 2 | 为什么需要及时响应代码审查请求？ | `engineering/team-management.md` | `## 代码审查文化` |

BM25 关键词一路正好补上这个短板。

## 实测过、但没采用的方案

### Rerank（cross-encoder 精排）

- 模型 `Xenova/bge-reranker-base`，候选 100
- **效果**：修好 2 条（desktop、prompt 都顶到第 1）
- **代价**：**33.5 秒 / 每次查询**（全量评估要 2.3 小时）
- **结论**：不划算。代码和配置开关保留（`rerank.enabled`），但默认关闭

顺带纠正两个先前的判断：
1. 不是打分 bug —— 查了模型配置，`num_labels = 1`，`scores[i]` 的读法是对的
2. #1/#2 不是 rerank 能救的 —— rerank 反而让它们更糟（期望文档压根不在前 100 的好位置）

### 提高向量候选数量（20 → 300）

- 根因：#1 的期望块全库真实名次是**第 2**，但 Chroma 的 HNSW 近似检索在 `nResults ≤ 100` 时把它整个漏掉了（`nResults ≥ 200` 才出现）
- 收益：Hit@5 98.4% → 98.8%（**只 +1 题**）
- 代价：每次多拉 15 倍数据
- 结论：收益太小，不做；且混合检索已经覆盖了这条

## 融合公式的选择（重要）

行业默认写法是**等权 RRF**，但在本项目实测**有害**：

| 融合方案 | Hit@5 | Hit@1 | MRR |
|---|---|---|---|
| 纯向量（原状） | 98.4% | 87.6% | 0.923 |
| RRF 等权 c=60（行业默认） | 98.8% | **86.4%** ↓ | 0.920 ↓ |
| RRF 等权 c=10 | 100.0% | 87.2% | 0.928 |
| RRF 向量1:BM25 0.3 | 98.4% | 89.6% | 0.935 |
| **归一化分数融合 向量0.7:BM25 0.3** | **100.0%** | **89.6%** | **0.944** |
| 归一化 + 绝对余弦（不做归一） | 99.2% | 88.0% | 0.933 |

原因：我们的中文分词是零依赖的**字符 bigram**，噪声比生产级分词器大，等权会让 BM25 的噪声把原本排第一的答案挤下去（实测 17 道）。所以必须**压低 BM25 权重**，并且**两路都要归一化**（不归一化的话两个分数尺度不可比，向量会被压制）。

最终配置（在实例 `knowledge.config.mjs` 里，可关）：

```js
retrieval: {
  hybrid: { enabled: true, candidates: 50, vectorWeight: 0.7, bm25Weight: 0.3 },
}
```

## 还有哪些已知可选项（未做）

| 优化 | 针对 | 说明 |
|---|---|---|
| 合并过短块 | 「## Q&A」这类 7 个字的块余弦虚高（实测拿到 0.705 排第一） | 切分后把过短块合并进相邻块 |
| 换生产级分词（jieba） | BM25 精度 | 需装原生模块，当前 bigram 已够用 |
| 块首拼章节路径 | 代码块 / 清单块语义弱 | 现在只拼了【文档标题】，可升级为【文档标题 > 章节】 |
| 查询改写 | 泛问题（如「如何优化提示」） | 需要额外 LLM 调用 |

> 注意：现在 Hit@5 已到 100%，**该指标饱和**，后续优化应看 Hit@1 / MRR / Recall@5。
