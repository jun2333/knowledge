## shouldComponentUpdate & pureComponent
### shouldComponentUpdate
一个配置更新策略的钩子，优先级高于pureComponent
类组件会调checkShouldComponentUpdate函数判断是否需要更新
```javascript
function checkShouldComponentUpdate(){
     if (typeof instance.shouldComponentUpdate === 'function') {
         return instance.shouldComponentUpdate(newProps,newState,nextContext)  /* shouldComponentUpdate 逻辑 */
     } 
    if (ctor.prototype && ctor.prototype.isPureReactComponent) {
        return  !shallowEqual(oldProps, newProps) || !shallowEqual(oldState, newState)
    }
}
```
### pureComponent
pureComponent组件会按照**浅比较**方式去对比state和props判断是否需要更新
shallowEqual浅比较的步骤：
1. 对比新老props和新老state是否相等
2. 判断新老props和新老state是否有存在不是对象或者为null的，存在则返回false
3. 对比新老props和新老state的Object.keys()返回的key数组长度是否相等
4. 遍历新老props和新老state的key判断值是否变化，这里对比值也是浅比较

pureComponent注意事项:
1. props的回调函数避免使用箭头函数，因为每次执行render都会返回新的回调函数，导致浅比较失效
2. 父组件为函数组件时，避免props的回调函数被定义在父组件内，得用useCallback缓存下(这也是useCallback最开始的目的)

## React.memo
可以理解成一个高阶组件，包了一层用于决定是否阻断React更新
### 用法
第一个参数：组件(类/函数)
第二个参数(选填)：函数，返回布尔类型决定是否需要重新渲染；当不填的时候按照**浅比较**方式对比props，相当于**仅比较 props**版本的 pureComponent

## 打破渲染限制
context/forceUpdate：可以穿透以上的阻断方案，包括pureComponent、React.memo以及shouldComponentUpdate

## 对渲染优化的思考
1. 不用太在意组件是否渲染，因为js运行速度远大于浏览器渲染DOM
2. 对于比较耗时的逻辑和大数据才需要进行渲染节流优化
3. 注意靠近顶层的节点发生没有必要的渲染
