## 模板语法vsJSX
模板语法是从UI出发，扩展逻辑
JSX是从描述逻辑出发，扩展UI的描述

## UI与逻辑的关系
简言之就是自变量x(状态)与因变量y(视图)的关系，自变量x(状态)发生了变化导致因变量y(视图)跟着变化

两种类型的因变量:
1. 无副作用的
2. 有副作用的
(副作用:函数执行过程中对外部产生影响,例如：修改函数外部变量、调用DOMAPI,I/O操作、控制台打印信息等)

满足如下两个条件的函数叫做**纯函数**：
1. 相同输入始终获得相同输出
2. 不会改变程序状态或引起副作用

## 发布订阅关系设计
1. 通过读取变量的值，在getter函数中建立发布订阅关系
2. 当变量值发生变化时，在setter函数中通知所有订阅者

### 如何建立发布订阅关系
state(状态)和effect(副作用)代表发布者、订阅者
state中的subs与effect之间建立互为引用的关系，即为发布订阅关系
```javascript
function subscript(effect,subs){
    subs.add(effect)
    effect.deps.add(subs)
}
```
### 如何通知所有订阅者
当state发生变化时，遍历subs中所有的effect,并执行其回调函数

## AOT(Ahead Of Time预编译) VS JIT(Just In Time即时编译)
现流行的前端框架中对AOT和JIT的应用上的侧重有所区别，比如：
使用模板语言的框架Angular、Vue、Svelte则能很好的从AOT中受益，通过预编译可以在寻找变化的UI过程中跳过静态的部分;而使用jsx的React却很难从AOT中受益，ES语法的灵活性很难进行静态分析~
因此前端框架也可按照AOT侧重程度进行分类，React则是重运行时框架

## Virtual DOM
用于描述UI的对象
工作原理可分两步：
1. 将"元素描述UI"转化成"Virtual DOM描述UI"
2. 对比前后VDOM变化，计算出UI的变化

VDOM优点：
1. 相较于DOM的体积优势
2. 相较于AOT更强大的描述能力
3. 多平台渲染能力

## 前端框架分类
按照因变量的最小粒度，可以分为应用级、组件级、元素级三种
应用级：建立自变量与应用之间的对应关系
组件级：建立自变量与组件之间的对应关系
元素级：建立自变量与元素之间的对应关系

三种主流技术：
1. 用于运行时建立自变量与因变量关系的细粒度更新
2. 用于编译时建立自变量与因变量关系的AOT
3. 用于运行时根据自变量变化算出UI变化的VDOM技术

svelte是极致的编译时框架
vue是极致的均衡型(AOT和VDOM)框架
react是极致的运行时框架
