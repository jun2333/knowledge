## 异步I/O

#### 阻塞、非阻塞

阻塞I/O：调用后需要等待内核响应，此时CPU处于等待状态

非阻塞I/O：调用后，内核立即响应，CPU可以去做别的事情（缺陷：立即响应的结果并非调用所需要的，因此需要轮询）

#### 轮询技术

现存轮询技术有如下：

read：在得到最终数据前，CPU一直处于等待状态，不断检查I/O状态，这是最原始最低效的轮询

select：在read基础上进行改进，通过文件描述符上的事件状态进行判断，若完成状态则使用read轮询，不过状态采取1024长度数组存储，所以同时只能检查1024个文件描述符

poll：与select不同的是poll采取链表存储状态，因此在长度上无限制，但是性能仍然不高

epoll：进入轮询时若没有检查到I/O事件，则进行休眠，直到事件唤醒，利用了事件通知、执行回调方式，而不是遍历查询，执行效率最高（缺陷：休眠的CPU并没有被利用起来）

#### 异步I/O

底层都是基于线程池实现，让部分线程用于轮询，一个线程用于计算。

*nix：自定义线程池

windows：IOCP(由系统内核管理线程池)

#### nodejs异步实现

几个重要概念：

1. 事件循环：nodejs的调用会创建类似while(true)的循环，每次循环称为Tick，每个Tick过程会检查是否有回调处理，...然后进行下次循环
2. 请求对象：js调用到内核执行过程中的一个中间产物，存储js层调用底层方法和参数(即：回调函数)，后续还存储执行结果

整个过程如下(以读取文件为例)：

js异步调用I/O -> 调用c++内建模块 -> libuv平台判断 -> 平台处理包装请求对象 -> 将请求对象推入线程池 -> 有空闲线程则立即执行并返回 -> 内核完成读取文件将结果存入请求对象result属性中并通知IOCP，并归还线程池 -> 事件循环中执行回调

#### 定时器：setTimeout、setInterval

实现上与异步I/O不同，调用时会将其回调函数存储到红黑树中，下次Tick开始每次循环都会检查是否超时，若超过则从红黑树中取出调用

#### process.nextTick

相对定时器，process.nextTick更为轻量，它是将回调函数存储到数组队列中，在进行下一次Tick之前执行回调函数

时间复杂度上红黑树O(logn)；而数组O(1)

#### setImmidiate

在表现上setImmidiate和process.nextTick几乎相同，但是在实现和原理上并不同：

- 存储上，setImmidiate是用链表存储回调函数，process.nextTick是用数组
- 执行先后顺序上，setImmidiate属于check观察者，process.nextTick属于idle观察者，Tick过程中，idle观察者先于I/O观察者，I/O观察者先于check观察者
- 具体表现上，一次Tick过程中，setImmidiate只执行链表中一个回调函数，process.nextTick则把数组中全部回调函数执行完

#### 事件循环的几个阶段

1. 定时器
2. I/O callback：执行tcp错误之类的回调
3. idle
4. poll轮询，执行回调队列
5. check setImmidiate并执行回调
6. close回调（如socket被关闭时进入此阶段）
